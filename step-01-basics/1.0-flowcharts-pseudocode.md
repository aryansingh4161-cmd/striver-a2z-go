# 1.0 Flowcharts and Pseudocode

Before writing code, write the **logic**. Flowcharts and pseudocode show the logic without any language syntax getting in the way.

**Problem → Algorithm → Flowchart → Pseudocode → Program**

## Flowchart symbols

| Shape | Meaning |
|---|---|
| Oval | Start / End |
| Parallelogram | Input / Output |
| Rectangle | Process (calculation, assignment) |
| Diamond | Yes/No decision |
| Arrow | Which step runs next |
| Small circle | Connector (joins parts of a big chart) |

**The token idea:** put a token on Start and move it along the arrows. A diamond sends it down **exactly one** branch. An arrow going back up makes a loop. Not every box runs, only the ones on the path the token takes.

Always label decision branches **Yes / No**.

## The 3 building blocks of every algorithm

1. **Sequence:** steps one after another (read length, width → area = l × w → print).
2. **Selection:** `if / else` (age >= 18 → eligible).
3. **Iteration:** loops (print 1 to N).

A loop always needs 4 answers:

| Question | Example: sum 1..N |
|---|---|
| Starting state? | `sum = 0, i = 1` |
| Keep going while? | `i <= N` |
| Repeated work? | `sum = sum + i` |
| Progress? | `i = i + 1` (forget this → infinite loop) |

## Pseudocode

Structured English. No fixed grammar. Just be **consistent and clear**.

```text
READ marks
IF marks < 0 OR marks > 100
    DISPLAY "Invalid"
ELSE IF marks >= 90
    DISPLAY "A"
ELSE
    DISPLAY "Not A"
END IF
```

Action words: `READ, DISPLAY, SET, IF, ELSE, WHILE, FOR, RETURN, STOP`.

## Lessons from the solved problems

- **Validate first, then compute.** An average of invalid marks means nothing.
- **Use a flag** (`pass := true`) to remember something across loop iterations.
- **Current champion pattern:** keep the best value seen so far, compare each new value with it. This is how "largest of N" becomes a simple loop.
  - Start the champion with the **first value**, not `-1` (fails for all-negative input).
- **In an `if / else if` chain, order matters.** The first true branch wins. Check `>= 90` before `>= 75`.
- **Digits trick:** `n % 10` gives the last digit, `n / 10` removes it.
- **Dry run with boundary values:** 0, 39/40, 100/101, ties, negatives.
